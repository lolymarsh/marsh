# 02 — Flow การทำงาน: Input → Output

> เปรียบเทียบ flow แบบมี/ไม่มี intercept (RTK) ตั้งแต่ผู้ใช้พิมพ์ ถึงได้คำตอบ
> อ่านก่อน: `01_mechanism.md`

## Flow เต็ม (มี RTK — hook mode)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. USER INPUT                                               │
│    คุณพิมพ์: "fix bug ใน customer handler"                   │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. AGENT                                                   │
│    อ่าน context + rules → วางแผน → ตัดสินใจรันคำสั่ง          │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. TOOL CALL (bash)                                        │
│    agent เรียก: git status                                  │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
              ╔════════════════════════════════╗
              ║ ★ INTERCEPT (hook) ตรงนี้ ★     ║
              ║  rewrite → rtk git status      ║
              ║    → รัน git จริง              ║
              ║    → กรอง/บีบ output           ║
              ║  (45 บรรทัด → 1-2 บรรทัด)      ║
              ╚════════════════════════════════╝
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. AGENT CONTEXT (จุดที่ประหยัด token)                     │
│    output บีบแล้วเข้าสู่ context                             │
│    git status → "* main...origin/main, ?? msg.md"          │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 5. REQUEST ไป MODEL (ไม่ผ่าน RTK)                          │
│    system + history + rules + tool output (บีบแล้ว)         │
│    → DeepSeek / Claude / Gemini / อื่นๆ                     │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 6. MODEL RESPONSE                                          │
│    อ่านน้อยลง → เข้าใจเร็ว → ตอบ/แก้โค้ดแม่นขึ้น             │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 7. OUTPUT → USER                                           │
│    ผลลัพธ์กลับมา: คำตอบ / ไฟล์ที่แก้ / diff                  │
└─────────────────────────────────────────────────────────────┘
```

## เปรียบเทียบ: มี RTK vs ไม่มี RTK

```
❌ ไม่มี RTK:                                ✅ มี RTK (hook/instruction):

git status เรียกตรงๆ                       git status → rtk git status
    │                                          │
    ▼                                          ▼
output ดิบ 45 บรรทัด                         output 1-2 บรรทัด
(ทุกบรรทัดเข้า context!)                    (เฉพาะสาระสำคัญ)
    │                                          │
    ▼                                          ▼
Model อ่าน 45 บรรทัดทุกครั้ง               Model อ่าน 2 บรรทัด
= เผา token ซ้ำๆ                          = ประหยัด 60-90%

ตัวอย่าง cargo test:                       cargo test → rtk cargo test
200+ บรรทัด (ผ่านทั้งหมด)                  FAILED: 0/15 tests
= เปลืองทั้งที่ไม่มีอะไรผิด                = เห็นผลทันที รู้ว่าไม่มี fail
```

## จุดที่ "ประหยัด" เกิดตรงไหน

```
token ที่ใช้ต่อรอบ = prompt + history + rules + TOOL OUTPUT + ...
                                          └────▲────┘
                                  RTK บีบตรงนี้
```

RTK ลดเฉพาะ **tool output** ที่จะเข้าสู่ context ในรอบถัดไป — ไม่ได้ลด
prompt, system prompt, หรือ response ของ model

## สรุป 5 บรรทัด

1. Intercept อยู่ระหว่าง **agent ↔ shell** (ชั้น tool call) — ไม่ใช่ระหว่าง user ↔ model
2. ทำงานเฉพาะ **ฝั่ง output** ของคำสั่ง
3. ประหยัดเพราะ output บีบแล้วไปอยู่ใน context ของรอบถัดไป
4. Hook mode = อัตโนมัติ (Claude Code/OpenCode/Cursor/Gemini) | Instruction mode = agent อ่าน rules แล้วทำเอง (Freebuff)
5. RTK ไม่แตะ request ไป model, system prompt, หรือ response ที่ model ตอบ
