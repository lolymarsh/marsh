Architecture Decision Matrix Guide

เลือก Stack ให้เหมาะสมกับขนาดงาน ไม่ให้เปิด Infra เกินความจำเป็น

แนะนำ Solo/Internal

💡 Tier 1: Lean Stack

Postgres-Only (Infra ตัวเดียวจบ)
  • Primary DB: PostgreSQL
  • Queue: SKIP LOCKED (River/pg-boss)
  • Realtime: LISTEN/NOTIFY + SSE
  • Cache: UNLOGGED TABLE
เหมาะกับ: Internal Tools, MVP, ผู้ใช้ < 1,000 Concurrent

🚀 Tier 2: Hybrid Stack

Postgres + Redis (High Read)
  • Primary DB: PostgreSQL
  • Cache & Queue: Redis Streams
  • Realtime: SSE / Redis PubSub
เหมาะกับ: Prod App ทั่วไป, มี Cache-aside ซ้ำๆ

🏢 Tier 3: Distributed

Enterprise / Multi-worker
  • DB: Postgres + Read Replicas
  • Cache: Redis Cluster
  • Queue: RabbitMQ (DLQ + Routing)
  • Realtime: WebSockets
เหมาะกับ: งาน Enterprise, High Concurrency
💡 ทำไมต้อง Postgres-Only Lean Stack สำหรับงานภายใน?

เพราะการใช้ Transactional Queue ใน PostgreSQL (`SKIP LOCKED`) สามารถทำ Transactional Job คือเขียนข้อมูลลงตารางหลักและใส่คิวใน Database Transaction เดียวกันได้ทันทีแบบ 100% ACID ทำให้หมดปัญหาเรื่อง Dual-write หลุด หรือ Redis ดับแล้วข้อมูลค้าง!

คัดลอกข้อความเรียบร้อย!
